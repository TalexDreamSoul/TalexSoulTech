# Release and Client Validation

## Goal

把已提交的 Paper 26 玩法版本作为唯一候选构件部署到 wlcb1，并用服务器、真实客户端与新区块负载证明其可运行、不可复制且没有持续 tick 回退。

## Source Context

- 功能提交：`fa95e52`（运行时与玩法现代化）。
- 集成提交：`f946cf2`（控制站点与资源包，包含前一提交）。
- 完成时本地与 `origin/main` 均为 `f946cf2057291f1073d37f86f8634446a5e0ff50`。
- 详细实现、验证结果与遗留事项见 `.trellis/workspace/TalexDreamSoul/journal-1.md` Session 1。

## Requirements

- 发布候选必须从包含上述两个提交的干净提交快照构建；当前工作树中其他窗口的未提交 `site/`、扩展运行时与 Agent/Trellis 初始化改动不得被带入候选。
- 使用 Java 25 完整构建并执行现有测试；最终 JAR 必须包含 `plugin.yml` 且声明 Paper 26 兼容入口。
- 重启前通过 RCON 确认在线玩家。若有人在线，停止发布并取得明确重启授权。
- 插件 JAR 先上传临时路径，再通过 `.new` 文件原子替换；替换前后检查 PluginManager quarantine，禁止直接覆盖正在监视的最终文件。
- 部署后必须验证容器健康、Paper 完整启动、TalexSoulTech `ENABLED`，以及 RCON `plugins` 可见。
- 资源包必须由仓库脚本从源码确定性生成、在线可下载且摘要匹配发布清单；未安装资源包时仍保留原版 fallback。
- Wilderness 在完成验收前保持默认关闭；只在明确测试世界启用，并只使用新生成区块验证矿物索引、消费状态和自然精英怪。
- 真实客户端必须覆盖向导书领取/右键、三类箱子权限和库存操作、方块破坏掉落，以及漏斗/活塞/爆炸/合成防复制路径。
- 记录启用前后的 TPS/MSPT 与新区块生成观察值；发现插件导致持续 tick 超时、数据丢失或复制漏洞时立即关闭 Wilderness 并回滚插件候选。

## Acceptance Criteria

- [ ] 候选从干净提交快照构建；Java 25 Maven 构建和全部现有测试通过。
- [ ] 最终 JAR 的提交来源、SHA-256、`plugin.yml` 与部署文件一致并被记录。
- [ ] 发布前确认无在线玩家，或已取得本次重启的明确授权。
- [ ] 原子替换完成，quarantine 无同名候选；容器 `healthy`、Paper `Done`、插件 `ENABLED`、RCON 可见。
- [ ] 资源包下载、摘要、模型选择器、原版 fallback 和八项自定义纹理在真实客户端通过。
- [ ] 向导书和铜/铁/虚空箱的点击、权限、拖拽、Shift、双击、掉落及防复制回归通过。
- [ ] 测试世界新生成区块能产生并消费 v2 矿位；配置变化后历史位置仍可识别，`RAW_GOLD_BLOCK` 不会作为奖励掉落。
- [ ] 只增强自然生成的白名单敌对生物；没有重复增强、全局实体扫描或异常实体增长。
- [ ] 受控新区块生成期间无插件导致的持续 TPS `< 19.5` 或 MSPT `>= 50ms`；观测原始值已写入验收记录。
- [ ] 验收失败时 Wilderness 已恢复关闭，旧 JAR 可原子回滚，玩家数据和箱子内容没有损坏。

## Non-Goals

- 不在本任务中合入当前其他窗口的未提交站点或扩展改动。
- 不在发布窗口顺带清理旧粒子库或 `EntityEffect` 的 deprecated 警告。
- 不扩大 Wilderness、箱子或资源包玩法范围；本任务只做发布与验收。
